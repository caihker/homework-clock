# v1.6.1 每天自动回到今天

2026-11-14（北京时间）。修复日常使用中的日期回退问题：真实模式下打开 App 或跨天时，右侧安排自动显示当天，不再需要手动翻页。

## 行为规则

| 场景 | 行为 |
| --- | --- |
| 上次使用是前一天，今天再打开 | 右侧直接显示今天；`lastActiveDate` 更新为今天 |
| 首次升级、状态里没有 `lastActiveDate` | 同样显示今天 |
| 同一天内手动查看其他日期后刷新 | 保留用户选择的日期（不强行拉回） |
| App 跨午夜仍保持打开 | 下一次计时刷新发现日期变化，自动切回今天并提示“新的一天” |
| 正在查看过去日期时点「添加安排」 | 先回到今天，再打开新增安排 |
| 正在查看未来日期时新增 | 保留该天，方便提前安排 |
| 演示时间模式 | 不受影响，保持演示日期 |

## 实现

- `store.dailyDate({ selectedDate, lastActiveDate, clockMode, today })`：纯函数，真实模式下只有 `lastActiveDate` 不是今天时才返回今天；演示模式原样返回。新增 1 项单测覆盖 5 种输入。
- `state.lastActiveDate` 随本机状态保存；旧状态默认在加载时补为今天。
- 加载时先按 `dailyDate` 校正选中日期；`syncToday()` 在计时循环中检测跨天，切换日期、重置筛选并持久化。
- `setDate()` 会标记 `lastActiveDate` 为今天，避免用户主动翻页后被计时循环拉回。
- 从过去日期新增时 `openTask()` 先切到今天；未来日期保持不变。
- 备份恢复后把 `lastActiveDate` 标记为今天，避免恢复完成立刻被跨天逻辑切走。
- 切换演示/真实时间、示例重置、外部状态更新路径同步维护 `lastActiveDate`。

## 局限

- 跨午夜采用“直接回到今天”的明确策略；若用户正好在午夜查看未来日期，也会被切回今天（符合本次“每天自动到当天”的要求）。
- 未在真实 iPad 上验证后台驻留跨午夜的计时器触发时机；逻辑同时依赖计时循环，恢复前台后会再次校正。
