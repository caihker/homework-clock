## 2. 优化原则与边界

**原则**

1. 先解决问题，后加功能：阶段 1、2 只处理缺陷与风险，不改变产品行为。
2. 数据优先：任何可能丢失计划、录音、历史的路径，优先级高于性能与体验。
3. 每阶段可独立发布：不把多个主题捆进一个版本，便于定位问题与回滚。
4. 零依赖：继续不引入 npm 运行时依赖；构建脚本只使用 Node 标准库。
5. 量化验收：每个阶段有数字目标和可复现步骤，验证记录写入 `docs/verification-vX.Y.Z.md`。
6. 版本纪律：版本号三处一致（`demo/package.json`、`demo/dist/index.html` 的入口 `?v=` 与设置页版本、`CHANGELOG.md`）；改 `dist/` 后必须 `npm run build` 并 `npm run check`。

**非目标（本期不做）**

- Family Controls / 应用限制：PWA 无法实现，维持“如实披露 + 结束强反馈”。
- 账号、云同步、远程家长端、后台推送服务。
- AI 自动排程、社交排名、积分体系。
- 为了“看起来现代”而更换框架或引入构建器。

## 4. 阶段 1：数据安全与可靠性（v1.3.0）

### 4.1 要解决的问题

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1-A | 损坏或未知版本的状态被示例数据静默覆盖 | `demo/dist/app.mjs:70-75`、`:200` | 计划/历史/录音永久丢失且无提示 |
| 1-B | 全局无错误边界 | `demo/dist/app.mjs:283-317`、`:604-606` | 单个字段类型损坏即白屏或停摆，无恢复入口 |
| 1-C | 每次操作重复写盘 2–3 次 | `app.mjs:200` 与 11 处 `persist();render()`、`:507-510` | 含录音时同步序列化整段 JSON，主线程卡顿 |
| 1-D | `notified` 无界增长、每秒全量扫描 | `app.mjs:604-606`、`demo/dist/reminder-events.mjs:15` | 长期使用后存储/CPU 缓慢增长 |
| 1-E | 多窗口不监听主数据键 | `app.mjs:675` 只监听 UPDATE_LOCK | 旧窗口显示过期数据，直到操作失败 |
| 1-F | 语法检查漏 2 个模块 | `demo/package.json` 的 `check` 漏 `turtle-travel.mjs`、`voice-pack.mjs` | 漏检形同虚设（目前靠测试兜住） |
| 1-G | 备份白名单与状态强耦合、僵尸字段 | `demo/dist/backup.mjs:20-24,86`、`app.mjs:58,79` | 未来加字段可能让“导出备份”直接抛错 |
| 1-H | 未声明最低系统版本 | 代码依赖 `dialog.showModal`、`crypto.randomUUID`、`:has`、`inert`，实际需 iPadOS ≥15.4 | 老设备异常且无说明 |

### 4.2 措施

1. **安全加载与恢复（1-A / 1-G）**
   - 解析失败、schema 不合法、`version` 高于当前支持版本时：先把原始字符串写入固定恢复键 `homework-clock-demo-v1-recovery`（只有内容变化时才覆盖）。
   - 进入“数据待恢复”只读态：禁止自动写盘，首页显示可操作提示（导出原始数据 / 从备份恢复 / 确认重置）。
   - 明确 `version > 1` 与 `version === 1` 两条分支，未来版本按“拒绝写入”处理，防止降级覆盖。
   - schema 校验抽成可复用函数，加载与跨窗口采纳统一使用；备份导入继续使用现有严格白名单校验，等阶段 4 引入 `schema.mjs` 后再合并。
2. **全局错误兜底（1-B）**
   - `window.onerror` / `unhandledrejection` 捕获后展示可恢复错误页，提供“导出当前数据”入口。
   - `render()` / `tick()` / `persist()` 内部加保护，单次失败不终止计时循环。
3. **单次写盘（1-C）**
   - 只保留一个写盘入口：`render()` 不写盘、由操作显式调用 `persist()`；或在保留 `render()` 写盘的前提下删除 11 处重复调用。
   - “保存设置”合并为一次 commit（1 次写盘）。
   - 写盘后更新保存状态文案，失败保留原数据。
4. **提醒扫描收敛（1-D）**
   - `notified` 的 key 增加日期前缀，只保留当天。
   - `collectDueReminders` 接收 `Set`，避免每秒重建全集。
5. **跨窗口同步（1-E）**
   - 监听主数据键的 `storage` 事件：本窗口无未保存内容时直接采纳；有未保存内容时提示“其他窗口已更新，点击重载”。
   - 与现有更新锁、草稿守卫复用同一判定。
6. **检查脚本补全（1-F）**
   - 新增 `demo/scripts/check-syntax.mjs` 遍历 `dist/*.mjs` + `dist/sw.js`，或把 `check` 改为 `for f in dist/*.mjs dist/sw.js; do node --check "$f" || exit 1; done`。
   - CI 使用同一命令，避免两套逻辑。
7. **文档与范围声明（1-H）**
   - 在 `README.md` 与 `demo/README.md` 写明最低 iPadOS 版本与依赖能力。
8. **验收与测试**
   - 新增测试 ≥15：损坏 JSON、`version=2`、部分任务非法、storage 抛错/配额、双窗口 `storage` 事件、`notified` 修剪、单次写盘断言、检查脚本覆盖。
   - 浏览器实测：注入损坏数据后不丢原始数据；双窗口一方保存另一方提示；模拟存储拒绝时保留原数据。

### 4.3 预期成果（可验收）

- 静默覆盖路径 0 条；任何无法解析或未知版本的数据 100% 进入 recovery 键，且首屏可见恢复入口。
- 普通操作写盘 1 次（保存设置 1 次）；测试断言写调用次数。
- `notified` 仅当天数据，长期使用不增长；每秒扫描量随当日通知数有界。
- 全部 20 个 mjs + `sw.js` 纳入 `npm run check`，CI 通过。
- `npm test` ≥215 项全绿；`npm run build` / `npm run check` 通过。
- 现有行为不变：计划、计时、录音、备份、更新全部回归通过；除错误提示外无 UI 布局变化。

### 4.4 风险与回滚

- 风险：只读态可能挡住正常启动；恢复逻辑本身出错。
- 应对：只读态仅在明确损坏/未来版本时触发，并加单元测试；保留 tag `v1.2.4`，异常时回退发布。
- 回滚：本阶段只改启动、持久化、提醒路径，不迁移数据格式；直接回退到 `v1.2.4` 代码即可，数据格式兼容。

### 4.5 完成记录（v1.3.0，2026-11-06）

- `README.md` 与 `demo/README.md` 标明最低 iPadOS 15.4。

## 5. 阶段 2：体积与首屏（v1.3.1）

| 编号 | 问题 | 证据 | 影响 |

| 2-A | 首屏图片约 5.7 MiB；1254×1254 用在 28–156px | `demo/dist/index.html:35,50,52,133,134`、`app.mjs:27` | 首屏慢、离线包大 |

| 2-D | `dist` 中约 11.4 MiB 未被引用素材 | `assets/category-3d-v2`、`category-flat-v1`、`motion` | 部署/下载/构建浪费 |

### 5.2 措施

1. **图片资产重制（2-A）**
   - 分类图标 1254×1254 → 128/192 WebP（显示 44–72px，2x/3x 用 192）。
   - 乌龟图标 → 192 或 256 WebP；陪伴乌龟 → 512 WebP（最大显示 156px）。
   - PNG 源保留在 `design-assets/`；`dist` 只放 WebP；同步更新 `sw.js` 清单与 CSS/JS 引用。
   - 等比缩放（`companion.mjs` 比例常量不变），截图对照做视觉回归。
2. **删除 `dist` 未引用素材（2-D）**
   - 删除 `assets/category-3d-v2/`、`assets/category-flat-v1/`、`assets/motion/`。
   - 未引用的 `cat.svg`、`comic-cat.svg`、`favicon.svg`、`OFL-*.txt`、`fonts/metadata.json` 移出离线清单（源文件按需保留在仓库，但不进 `dist`）。
   - `build-offline.mjs` 增加告警：`dist` 中未被引用且未进清单的资产。
3. **字体策略（2-B，需决策 D1）**
   - 方案 A（推荐）：保留 core 子集（约 0.2 MiB）预缓存；全量 CJK 移出首装，遇到子集外字形时按需取用，离线回退系统字体。
   - 方案 B（保守）：保留全量，只完成第一批优化，离线包目标 ≤11 MiB。
   - 选择 A 时需在设置/README 说明“极少见字离线时使用系统字体”。
4. **动画按需（2-C，需决策 D2）**
   - 仅预缓存当前所选陪伴形象的动画；切换到另一形象时再补齐，离线不可用时回退静态帧（已有 `still.png` 机制）。
5. **离线准备提速（2-E）**
   - `fillCache` 对小文件（如 <200 KB）允许 2–3 并发，大文件仍串行。
   - 冷启动用持久化“已完整”标记替代 76 次 `cache.match`，版本变化时再全量校验。
   - 回前台 `refresh()` 节流到 ≥30 分钟或用户手动触发。
   - 失败资源保持指数退避重试与“继续准备”入口。
6. **预算测试（2-F）**
   - 新增清单总量上限（≤11 MiB；字体按需后 ≤6 MiB）、首屏图片字节上限（≤0.3 MiB）、单文件上限测试。
   - 修改 `offline-assets` 为“必需集必须包含 + 预算断言”，不再要求所有 woff2 都必须进包。
7. **CSS 请求合并（2-G）**
   - 机械合并为 1–3 个 CSS（保持加载顺序），`font-faces.css` 的 `unicode-range` 保留。
   - 真正的 token 化与去重放阶段 4。

### 5.3 预期成果（可验收）

- 首屏图片：约 5.7 MiB → ≤0.3 MiB（约 −95%）。
- 离线包：17.64 MiB → ≤11 MiB（第一批）；字体按需后 ≤6 MiB。
- `demo/dist` 部署体积：约 29 MB → ≤13 MB（删除约 11.4 MiB 未引用素材 + 图片瘦身）。
- 首次离线准备：本地 20 Mbps 模拟网络下耗时 −50% 以上；弱网失败重试成功率提升。
- 首屏请求：CSS 13→≤3；图片请求字节 −95%。
- CI 新增 3 项预算断言；`npm test` 全绿；浏览器视觉回归无布局差异。
- 历史故障（下载中断、停在 N/M）不再因体积放大而更容易触发。

### 5.4 风险与回滚

- 风险：WebP 在旧 iPadOS 的兼容（iOS 14+ 均支持，风险低）；替换图片后乌龟对齐偏移；字体按需导致罕见字回退系统字体的观感差异。
- 回滚：资产替换与清单更新是独立提交，可单独回退；字体策略保留开关，必要时恢复全量缓存。
