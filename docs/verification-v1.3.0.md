# v1.3.0 数据安全与可靠性

2026-11-06（北京时间）。本版对应 [分阶段优化方案](optimization-plan.md) 阶段 1：只修复问题，不改变产品交互路径。保留漫画界面、时间规则、录音、备份、更新与离线方式。

## 发现与修复

- **损坏或未来版本数据被静默覆盖**：此前 JSON 解析失败或 `version !== 1` 时直接生成示例数据，随后的自动保存会把原数据永久覆盖。现在先按字节把原始内容写入 `homework-clock-demo-v1-recovery` 恢复副本；无法安全读取时进入只读态（暂停自动保存），首页显示可操作的恢复提示条：导出原始数据、从备份恢复、用示例数据重新开始。
- **未来版本识别**：`version > 1` 单独标记为「来自更新版本」，拒绝写入，避免降级覆盖；`version === 1` 但结构不合法按损坏处理。
- **部分记录损坏**：架构校验通过但个别安排/历史记录不合法时，跳过坏记录并计数，保留原始字节到恢复副本，提示「部分记录无法读取」，其余数据照常保存。
- **全局错误兜底**：增加 `error` / `unhandledrejection` 监听；启动、渲染或计时异常时暂停自动保存、停止计时循环并显示提示条，不再无声停摆。计时回调单独捕获异常。提示条提供「导出原始数据」「刷新重试」「保存当前数据并继续」（数据损坏时显示「用示例数据重新开始」）；恢复出口会重置提醒窗口并重新启动前台计时循环，同时重新开放错误上报，避免错误恢复后计时冻结或刷新后反复冻结。
- **恢复副本写入失败**：恢复副本写不进去时同样进入只读态，并用内存中的原始字节导出，避免归一化结果覆盖原始数据；导出只在恢复副本与原始字节都不存在时才使用当前数据，并显示对应文件名与提示。
- **恢复出口完整**：错误、损坏、未来版本、部分损坏与跨窗口采纳都有可操作出口；`reportFatal` 清空计时句柄，reset / 备份恢复 / 跨窗口采纳 / 启动统一调用 `startTicking()` 重启计时循环，不会出现“数据恢复但计时冻结”的静默降级。
- **重复写盘**：`render()` 不再写盘，普通增删改与设置保存只写 1 次（开始/结束计时等会话操作先归档历史再存会话，可能 2 次）；`persist()` 在恢复只读态下拒绝自动写入，并同步保存状态文案。
- **提醒记录无界增长**：提醒 key 增加日期前缀（`日期:任务:开始:结束:事件`），`notified` 只保留当天；`collectDueReminders` 接受数组或 `Set` 且不修改调用方集合。
- **多窗口不同步**：监听主数据键 `storage` 事件；无编辑且不在计时中时直接采纳并提示，有编辑时先确认；确认框已打开或正在导入时只提示，不替换当前操作的回调；采纳时重置提醒窗口，远端数据含坏记录时同样保留恢复副本并提示。
- **恢复副本管理**：设置「本机」页新增「导出恢复副本 / 删除恢复副本」，刷新或恢复备份后仍可导出或清理，避免恢复键长期占用本机空间。
- **检查脚本漏检**：新增 `scripts/check-syntax.mjs` 遍历 `dist/*.mjs` 与 `sw.js`，`npm run check` 改为复用；补上此前漏检的 `voice-pack.mjs`、`turtle-travel.mjs`。
- **共享常量**：任务类型收敛到 `core.mjs` 的 `TASK_TYPES`，`backup.mjs`、`reminder-events.mjs`、`store.mjs` 共用；新增 `store.mjs` 承载解析、校验、归一化与恢复键。
- **文档**：`README.md` 与 `demo/README.md` 标明最低 iPadOS 15.4；补充恢复提示与检查脚本说明。

## 数据兼容与回滚

- 存储格式仍为 `version: 1`，未迁移字段；恢复只影响读取路径。旧版本写入的 `notified` 无日期前缀，首次加载会被剪除（不会重复补播过去的事件）。
- 新增本机恢复键 `homework-clock-demo-v1-recovery`，内容为最近一次无法读取的原始字节；重置或恢复备份后仍保留，可在首页提示条或「设置 → 本机」导出，也可手动删除。
- 浏览器验证使用 Chrome 无头模式；恢复提示、正常启动、部分损坏与未来版本四个场景均通过，详见上表。
- 回滚：整版回退到 `v1.2.4` 即可，旧版本会忽略恢复键；但旧版本仍存在静默覆盖问题，不建议长期停留。

## 局限

- 未在真实 iPad 上运行：恢复提示条的触控、VoiceOver 播报、错误兜底的真实触发路径、软键盘与 safe-area 表现需真机确认。
- 浏览器验证使用 Chrome 无头模式，非 iPad Safari；iOS 的 localStorage 配额、PWA 与 Safari 存储隔离、更新激活时序仍需按发布流程实测。
- 未执行 v1.2.4 → v1.3.0 的真实一键更新；升级兼容由「旧数据只读加载」单元测试与浏览器种子场景覆盖。
- 错误恢复后的计时重启由源码守卫测试覆盖，本轮未在浏览器注入真实运行时错误验证完整恢复路径，需真机或后续 E2E 补测。
- 阶段 1 不改变任何产品交互；「下一项」、能力披露、草稿保护等仍留在阶段 3。
