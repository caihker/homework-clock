## D1 字体按需（方案 A）

- 全量 CJK 字体（`homework-*.woff2`，约 6.2 MB）移出离线清单；core 子集（约 0.2 MB）继续预缓存并 preload。
- 罕见字在线按需加载；离线请求失败时回退系统字体。
- 全量字体仍部署供在线使用，但不进入 SW 清单；SW 的 `assets.has()` 判断让请求直接走网络，不会被旧缓存污染。
- `build-offline.mjs` 的 `isLazyAsset()` 统一标记懒加载资源；离线清单测试区分“core 必须进包 / full 必须懒加载”。

## D2 动画按需（方案 A）

- 立体乌龟 6 帧（约 1.2 MB）不再预缓存；默认原版动画继续完整缓存。
- 离线或加载失败时回退已缓存的 `motion-solid/still.png`；失败后记住回退状态避免每秒重试，联网后允许再次加载。
- 设置页立体预览改为静态帧，避免打开应用就预取动画。
- Chrome 验证：临时移除立体动画帧后显示静态回退、无破图；恢复后正常。

## 2-E 离线准备

- **小文件并发**：≤256 KB 的资源最多 3 个并发下载；大文件继续串行，避免 iPad 内存压力。进度事件与重试次数保持不变。
- **完整性快路径**：安装/修复完成后在缓存中写入 `./.homework-clock-ready` 标记；冷启动先用标记 + `index.html`/`app.mjs` 哨兵校验，跳过逐项 `cache.match`。
- **标记失效**：任一清单内资源被请求且缺失时先删除标记再修复；更新与激活路径强制全量校验（`cacheStatus({ full: true })`），避免标记过期导致不完整版本被应用。
- **回前台节流**：`pwa.mjs` 的可见性刷新限制为至少相隔 30 分钟；手动「检查更新」不受影响。

## 2-G CSS 合并

- 13 个 CSS 源文件移到 `demo/styles/`，新增 `scripts/build-css.mjs` 按原 `<link>` 顺序拼接为 `demo/dist/site.css`（约 205 KB）。
- `index.html` 只保留一个 `site.css` 链接；`npm run build` 先构建 CSS 再生成离线清单，`npm run check` 验证 CSS 与源文件一致。
- 顺序由 `STYLE_ORDER` 固定，`build-css.test.mjs` 断言产物等于有序拼接、页面只有一个样式表链接、所有源文件恰好覆盖一次。
- 横竖屏截图与合并前一致，无视觉回归。
