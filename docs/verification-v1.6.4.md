# v1.6.4 整体复查与边界修复

2026-11-14（北京时间）。对 v1.5–v1.6.3 的功能做了一次整体审计，修复备份、恢复、记事、跨午夜和过去日期等边界问题。

## 修复

### P0：备份导出失败

- 原因：v1.6.1 新增的 `state.lastActiveDate` 没有加入备份白名单，正常状态调用 `createBackup()` 会抛“格式不正确”，从 v1.6.1 起导出备份 100% 失败；恢复副本也无法回灌。
- 修复：白名单加入 `lastActiveDate`，并随备份导出/恢复；补充真实状态往返测试。
- 同时增强兼容：
  - 良性未知顶层字段被忽略，仍拒绝 `__proto__`、`constructor`、`prototype` 等原型键。
  - 仅含 `ms` 的旧专注记录会补齐 id/taskId/date，而不是阻断整份备份。

### P1：恢复备份时丢失进行中的计时

- 恢复前检查 `state.session`；若有计时，阻止恢复并提示“请先结束或暂停计时”，不再直接替换状态导致未归档的专注时间消失。
- 确认文案同时提示当前有计时进行中。

### P2：记事与更新/同步

- `#note-dialog` 纳入更新保护的 `pendingAction`：打开记事编辑时不会被更新/跨窗口同步静默替换。
- 采纳其他窗口数据后关闭残留的编辑弹窗，避免旧表单继续提交。
- 若保存时原记事已被另一窗口删除，改为另存为新记事并明确提示，不再误报“已更新”。
- 记事删除按钮的读屏标签带出记事摘要；iPad 触控区 44px。

### P2：跨午夜与日期

- `openTask()` / `openNote()` 记录打开时的日期；编辑已有安排保留原日期，新安排/新记事使用打开时的日期。
- `syncToday()` 在安排/记事弹窗打开时推迟跨天切换，关闭后再切到新一天。
- 过去日期的学习任务点「确认完成」现在直接打开完成弹窗，不再误开编辑框。
- 「复制这一天」跳过目标日已存在的同文记事，避免重复累积。

### P2：其他一致性

- `adoptStoredState()` 的丢弃计数补上记事和常用计划，与启动加载的 `inspectStorage()` 一致，避免“有 0 条记录无法读取”。
- 备份说明文案更新为包含计划、记事、常用计划、专注记录、家庭设置和录音。

## 局限

- 备份仍要求已知字段结构；未来新增字段需要同步维护白名单（已用良性未知字段兼容缓解顶层问题）。
- 恢复备份阻止进行中的计时，需要用户先结束/暂停再重试；这是为避免静默丢数据的有意取舍。
- 未在真实 iPad Safari 上验证读屏、触控与跨午夜后台行为。
- 未做 GitHub Release 资产更新（Pages 会随本次推送自动发布）。
